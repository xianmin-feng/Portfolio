Spatial OS Navigation & System Bar

Prototyping foundational system UI for the next-generation Horizon OS — System Bar, Navigator, Window Continuity, and Settings shipped to production.

Horizon OS System UI Unity 3D C# VR / MR Shipped Product

Overview

At Meta, I prototyped foundational system features for the next-generation Horizon OS — the surfaces users see and touch every time they put on a headset. The work covered four interconnected pillars: Navigator, System Bar, Window Continuity, and Settings. Each one shipped to production and shaped navigation consistency across the platform.

System Bar

The persistent navigation surface that anchors every spatial experience. I prototyped 8 layout configurations exploring how the bar could feel always-accessible without feeling intrusive — spacing, density, position relative to the user's gaze, and how it responds when the user moves through space. The selected configuration shipped and influenced patterns across other system surfaces.

Navigator

The user's home base — how you launch apps, switch contexts, and orient yourself in the system. I built the interaction model in working code, tuning the feel of how tiles surface, how the focus moves under your gaze, and how transitions cushion between states.

Window Continuity

How windows persist, follow, and respect spatial relationships when users move through their environment. Prototyped the behaviors that make windows feel like physical objects with intent — they remember where they belong, but stay reachable when you walk away.

Settings

System settings as a first-class spatial surface, not a flat menu transplanted from 2D. Prototyped how toggles, sliders, and panels feel in three dimensions — what depth, focus, and parallax do for legibility and control.

Impact

The work shipped to production and influenced the launch strategy for the next-generation Horizon OS. The 8 system-bar layout options established a vocabulary the team could reason about — turning subjective debate into concrete A/B-testable variants. Each prototype gave leadership a felt-rather-than-described version of the future, accelerating go/no-go decisions and aligning engineering on the implementation early.

The Takeaway

System UI lives or dies by the small stuff — the timing of a transition, the bias of a focus animation, the weight of a glance. Working in code meant every “what if” could be felt within hours, and the right answer surfaced from the prototypes themselves rather than from arguments about mockups.
